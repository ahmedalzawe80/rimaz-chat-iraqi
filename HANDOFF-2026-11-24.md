## PR #3 — application repairs

### Resource lifecycle
1. Private media tickets are reused for the same account/file, refresh idle expiry, cap at 32 per account and 4,096 process-wide, and retain participant authorization checks.
2. Startup orphan sessions receive a 60-second reconnect grace, then batch cleanup with one save, rollback and retry.
3. Room runtime cleanup is unified across leave, move, disconnect, global kick/ban, member-card kick/ban and room ban. Empty maps are removed and peers notified.
4. Room deletion evicts connected users and clears room/voice state only after successful save.
5. Public 24-hour retention saves before broadcasting deletions or unlinking media; failed saves restore collections and keep files/events unchanged.

### Transaction and permission repairs added in this continuation
- Announcement publish/delete now persist before socket events; failed saves restore prior state. Temporary expiry and permanent repeat timers retry after transient save failure.
- Admin message deletion, profile edits, likes/points, avatar deletion, room ban/mute, unmute/unban, ignore toggles, notification read-all and wall controls roll back on failed saves.
- Member-card global ban, room ban/mute, likes, VIP and gift actions persist before notification/disconnect side effects and restore old state on failure.
- Public upload replacement/deletion uses `removePublicUploadIfUnreferenced` to avoid unlinking shared files.
- Session creation, registration and guest creation restore session/account/profile/member-number/bootstrap state on failure.
- Notification/login-history writes, expired room/global ban cleanup, expired VIP/rank cleanup, guest entry status, profile-status migration and admin audit writes are rollback-safe.
- `permission_manage` no longer bypasses generic higher-rank protection for moderation/profile actions. Only the account-permission editor has an explicit exception, and it cannot grant permissions the acting manager does not hold.

### Container and repository safety
- Docker now uses `node:24-bookworm-slim` and sets `NODE_ENV=production`.
- CI uses Node 24 and builds the production image.
- `.dockerignore` excludes environment secrets, certificates, backups, database files, runtime data, uploads and private media.
- Node 20 reached EOL on 2026-04-30. Node 24 is LTS through 2028-04-30 (official Node release schedule).
- Open gap: no `package-lock.json` or npm shrinkwrap exists. Docker still uses `npm install --omit=dev`, not `npm ci`; dependency resolution is not fully reproducible. Generate a genuine lockfile from the trusted npm registry, validate it on Node 24, then switch to `npm ci --omit=dev`. Never invent integrity hashes.
